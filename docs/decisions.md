# Decisions taken during implementation

Rulings made while executing [the plan](superpowers/plans/2026-08-21-dsh-desktop.md) against [the design](2026-08-21-dsh-desktop-design.md), preserved so they can be revisited. Each states what was decided, why, and what it costs if the call was wrong.

- `.gitignore` gains `.superpowers/` — the SDD workspace lives at the repo root and must never be committed. Cost if wrong: none.
- drop the unused `serverStatus()` export from T4 — YAGNI, and the reviewer would flag it as dead. Cost if wrong: T5 needs a status getter added back, one line.
- correct expected test counts to 7 (T2) and 10 (T3) — a wrong count trains implementers to ignore expected output. Cost if wrong: none.
- T6 gains an explicit note that `hooks.json`'s port and `config.json`'s `notifyPort` are one value in two files, with the sync instruction. Not unified into a generated file: `hooks.json` is read by the harness, not by this app, and generating it would add a build step for one integer. Cost if wrong: a user who edits `notifyPort` loses notifications until they edit both.
- strip the dead `raw = ...` line from T5's icon generator. Cost if wrong: none.
- `desktop.patch.yml` was written in plugin-tree syntax (`- dsh-host-webserver:`), but `--patch` takes a PATCH LIST whose rows target entries by `id`. Corrected to `- id: webserver / config: {host, port}`. `host` must be restated because `applyEntryPatches` assigns the row's whole `config` (vendor/include/src/index.ts:120-123) and the webserver schema marks host and port `.required()`. Cost if wrong: the harness boots on the default 3080 and the app's port discovery still works, but a hand-run `dsh web` would then collide with it.
- Task 6's hooks-bridge patch likewise corrected — the bridge is absent from the web profile, so it is an `insert` row carrying its own `config`, not a patch of a nonexistent entry. Cost if wrong: the Stop hook never registers and notifications silently never fire.
- added a `--dump-config` verification step to Task 4, because an unmatched patch id only warns and is skipped (vendor/include/src/index.ts:112) — a silent failure that would otherwise surface as a mysterious port collision much later. Cost if wrong: one extra command per run-through.
- reviewer's "no grandchild test" finding is plan-mandated and NOT a defect — Task 3 exists solely to add that test and to prove it fails when stopGroup is downgraded to child.kill(). Deferring to Task 3 rather than duplicating it here. Cost if wrong: the riskiest behavior stays uncovered for exactly one task boundary; Task 3 closes it immediately.
- the "new stop tests bypass afterEach cleanup" finding is inherited from the brief text, but it is a real defect, not a plan choice — it already leaked a process during the implementer's own mutation check. Fixing rather than deferring. Cost if wrong: none; the fix is one assignment per test.
- the plan's spawn argv was wrong — `dsh web --no-open --patch F` fails with "unknown option '--patch'" because `web` aliases `--profile web` and launcher flags must precede it (apps/cli/src/args.ts:11); the first unrecognized token starts the INNER args. Correct form is `dsh --profile web --patch F --no-open`. The Task 4 implementer found and fixed this in server.ts (Task 2's file) plus its one test. Accepting the cross-task fix rather than reverting and re-running Task 2: the app cannot boot at all without it, and it is 2 lines. Plan text corrected so Tasks 6-7 do not repeat it. Cost if wrong: the fix rides in Task 4's commit rather than Task 2's, so `git log` attributes it to the wrong task.
- the plan AND spec both specified the wrong spawn argv — `dsh web --no-open --patch F` fails with "unknown option '--patch'" because `web` aliases `--profile web` and launcher flags must precede it (apps/cli/src/args.ts:11); the first unrecognized token starts the INNER args. Correct: `dsh --profile web --patch F --no-open`. The Task 4 implementer found and fixed this in server.ts (Task 2's file) plus its one test. Accepting the cross-task fix rather than reverting to re-run Task 2: the app cannot boot at all without it, and it is 2 lines. Plan and spec both corrected so Tasks 6-7 do not repeat it. Cost if wrong: the fix rides in Task 4's commit, so git log attributes it to the wrong task.
- CRITICAL confirmed real — `startServer` spawns synchronously but `server` is only assigned when the promise resolves, so quitting during the up-to-60s boot window leaves `before-quit` with `server === undefined`, no preventDefault, and a surviving detached child + node-pty grandchildren. Fix by adding an `onSpawned?: (stop: () => Promise<void>) => void` callback to StartOptions, invoked synchronously right after spawn, and having index.ts hold it as a pending stop. Chose this over awaiting the in-flight boot promise, which would hang quit for the full 60s timeout when the server never reports ready. Cost if wrong: one extra optional callback on an interface only this app consumes.
- SUPERSEDES the earlier no-API-key ruling. The user supplied local Ollama; their ~/.dsh/settings.yaml already sets agent-default-model to qwen3.8:27b-mxfp8 over an OpenAI-compatible route, and settings.yaml is the user-settings layer applying to every profile — so a harness the app spawns inherits it with no overlay. End-to-end Stop-hook verification is therefore possible and was ordered. Cost if wrong: none; it strictly adds evidence.
- config moves from <app>/config.json to $DSH_HOME/desktop.json (DSH_HOME defaults to ~/.dsh, matching packages/util/home-paths). No compatibility shim for the old location — the harness's own pre-release stance is foundation over shims, and this app has exactly one user. Cost if wrong: the user re-enters three settings once.
- npx mode is broken by a defect in MY plan text — `npx -y pkg@ver --profile web ...` lets npm exec consume --profile/--patch/--no-open as its own flags. The documented form is `npm exec <pkg> -- <args>`, so a `--` separator must precede the harness's arguments. Fixing rather than deferring: npx mode is the entire point of Task 8 and is unusable without it. Cost if wrong: npx mode stays broken and only local mode works.
- the implementer corrected a self-contradicting assertion I wrote in the Task 8 test (`expect(spec.args).not.toContain('web')` — but 'web' IS in args, as the value of --profile). Accepting the correction; the assertion was wrong, not the code.
- this is NOT a code defect. Controller verified the registry is reachable (HTTP 200, tarball 206) and that @deepseek-ai/dsh@0.1.1-rc.2 has 62 direct workspace dependencies whose transitive tree includes native modules (node-pty, sharp, koffi). A cold npx install of that tree is legitimately minutes. Accepting npx mode as IMPLEMENTED-BUT-UNVERIFIED rather than blocking the plan. Cost if wrong: npx mode does not work and only local mode is usable.
- bundling the Minor (trimmed vs untrimmed DSH_HOME) into the Important's fix round instead of deferring it. Normally minors never enter the loop, but this one is a one-line divergence from the harness's own resolveDshHome inside the very function being edited, so deferring it costs more than fixing it. Cost if wrong: negligible.
- CRITICAL is MY plan defect — tests/smoke.spec.ts greps `pgrep -fl "dsh web"` for orphans, but the argv became `dsh --profile web --patch ...` in Task 4's fix, so the substring never matches and `expect(survivors).toBe('')` passes unconditionally. The only test covering the packaged artifact's orphan behavior has been vacuous since it was written. Must be fixed and proven non-vacuous. Cost if wrong: a packaged app that leaks harness children ships with a green test.
- asar:false accepted as diagnosis but narrowed — asarUnpack for just desktop.patch.yml and hooks.json preserves archiving for dist/assets, which only Electron's own asar-aware Node reads. Ordering the narrower fix with a fallback to asar:false if it does not work. Cost if wrong: one extra build cycle; asar:false already works.
- dispatching ONE fix wave (per skill: never one fixer per finding) covering both Criticals, Importants 3/4/5/6/7/8, and the one-line globalShortcut minor. Folding Important 4 and 5 into a single fix — generating desktop.patch.yml AND hooks.json at boot with resolved paths and the configured notifyPort kills both the hardcoded dev path and the port-duplication bug at once. Cost if wrong: one more review cycle.
- Important 8 (window-all-closed quits the app) — fixing. A tray app whose tray is pointless once you close the window is incoherent; quit stays available via tray Quit and Cmd+Q, both of which route through before-quit's reaping path. This is a deliberate behavior change, not a bug fix. Cost if wrong: the user closes the window expecting the app to exit and it keeps running in the tray.
Parked residual: a DELIBERATE second Cmd+Q during the <=4s reap window can exit while the group has only been SIGTERMed. Ruling: accepted — it requires the user to force-quit twice on purpose, and the first quit already signalled the group. Cost if wrong: a determined double-quit can leave a harness child behind.
Parked residual: a genuinely SIGKILL-immune child could hold shutdown up to the 60s timeout. Ruling: accepted — an unkillable process is an OS-level condition this app cannot fix. Cost if wrong: quit hangs up to 60s in a situation that should not occur.
Parked residual: stopGroup's already-exited branch signals -pid after Node may have reaped it (recycled-pid risk). Ruling: accepted, JSDoc-documented — needs full pid-space wraparound AND the recycled pid to be a group leader. Cost if wrong: a signal to an unrelated process group, vanishingly unlikely.
Parked residual (cosmetic): the first boot never sets 'starting' on the tray; only restart does. Ruling: left alone — not worth a fix wave. Cost if wrong: the tray shows its initial state a moment longer than ideal on launch.
